# Analog macro integration / PnR status



## C soft-stdcell signoff result

The C integration now has a soft stdcell implementation selected by
`scripts/gen_analog_pnr_config.py --soft-stdcell`:

```text
TX: sky130_fd_sc_hd__inv_1 -> inv_4 -> inv_16
RX: sky130_fd_sc_hd__inv_4
```

This is a physical standard-cell implementation of the same canonical
`VDD/VSS/IN/OUT` interface.  It deliberately reuses verified stdcells and does
not claim the original transistor-level OA artwork.

Remaining non-signoff warnings from LibreLane are max-slew (88) and max-cap
(13) checks.  They are reported by the flow but do not gate this run; they are
not claimed as closed signoff limits.

The hard macro views in `analog/macros/` are now physical stdcell layouts
with DRC/LVS/PEX evidence, but the C top uses the soft implementation above.
The RX hard macro is a 3-parallel-inverter physical macro; the original
nonlinear-PMOS feedback is not present in that hard macro and is documented as
a topology deviation, not silently substituted.

## LibreLane run

Use the provided Nix shell:

```bash
nix-shell /opt/librelane --run \
  'librelane --manual-pdk --pdk-root <sky130-version> -p sky130A \
   -s sky130_fd_sc_hd build/analog_pnr_sky130/librelane.yaml'
```

The config is generated by:

```bash
python3 scripts/gen_analog_pnr_config.py --soft-stdcell \
  --package out/sky130-soc --out build/analog_pnr_sky130
```

The source macro GDS views are **abstract-only**: they contain met1/pin shapes
(and, for RX, nwell/li1 pin shapes) but no `diff`, `poly` or full transistor
stack.  `verification/analog/gds_audit.py` records this explicitly and the
macro manifests mark `physical_layout: false`.  The latest completed flow used
these met1 pin rectangles and ran all 80 stages (`analog_link_pins`).  A subsequent VPWR/VGND power-domain experiment stopped
at PDN generation because the macro PDN grid had no shapes; that experiment is
not counted as a completed flow.  The completed run is **not a signoff pass**:

```text
3 XOR differences
98 Magic DRC errors (nwell.4, LU.2, LU.3)
59 LVS errors
setup timing violations (no characterized macro timing)
```

Root causes are explicit:

- macro LEF pins are now GDS met1.pin rectangles, but the integrated top still
  has nwell tap/latch-up and LVS connectivity errors; these are not closed by
  pin extraction alone;
- the source GDS is not a transistor layout (`diff`/`poly`/`li1` missing), so
  standalone macro DRC/LVS/PEX cannot be treated as physical signoff;
- `macro.lib` is an analog black box with no timing arcs;
- the digital top has no characterized analog macro timing and the original
  macro layouts were not re-hardened for this top-level PDK integration.

The package staging (`make analog-package`) provides the available abstract
GDS/LEF/black-box Liberty/Verilog views and a `librelane_macros.yaml` fragment,
but does not claim that the resulting routed GDS is DRC/LVS/timing clean.  The current VPWR/VGND
attempt also fails at PDN (`PDN-0232/0233`), so power-grid closure is a blocker.

## Physical source inventory

The abstract-GDS finding is not a pin-extraction problem:

| source | GDS layers present | missing physical layers |
|---|---|---|
| `Inv_Transmitter.gds` | met1 draw/pin + PR boundary | diff, poly, li1 |
| `Res_FB_Inv.gds` | nwell/poly-pin/li1/met1 draw+pin + PR boundary | diff |

The real layouts exist only as OpenAccess views
(`Inverter_Based_Tx/Full_TX/layout/layout.oa` and
`Resistive_FB_inverter/.../layout.oa`).  The environment has no
`strmout`/`oa2gds`/OA runtime, so those views could not be streamed to GDS.
An ALIGN sky130 experiment generated a layout, but its PDK abstraction uses
different GDS layer numbers and no real nwell/diff stack; it is not acceptable
sky130 signoff evidence and was not promoted.

A fixed-device Magic/KLayout assembly prototype was DRC-clean for a single
inverter, but it is not a complete macro and its routing/LVS has not been
closed; it is not committed as a signoff view.

## What is still required for C signoff

0. Replace the abstract macro GDS with a physical transistor layout (or export
   the original `layout.oa` to GDS), then re-extract LEF/PEX/LVS views.
1. Keep the GDS met1.pin geometry, and resolve the nwell.4/LU.2/LU.3 latch-up
   and tap findings in the integrated top.
2. Re-run macro DRC/LVS against the **renamed, PR-boundary-added** GDS.
3. Add characterized macro Liberty/SPEF or explicitly black-box timing with a
   documented STA limitation.
4. Resolve top-level power/PDN connectivity (macro VDD/VSS).
5. Fix routing/setup and re-run post-route STA, DRC and LVS.
